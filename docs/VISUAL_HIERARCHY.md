# Visual Hierarchy Standards

## Heading Semantics

1. `#` (H1) = Book/Page title.
2. `##` (H2) = Major section.
3. `###` (H3) = Topic unit.
4. `####` (H4) = Detail/procedure.
5. Do not skip heading levels.

## Lists, Tables, and Code Blocks

6. Ordered lists for procedures.
7. Unordered lists for grouped concepts.
8. Definition lists for glossary-like sections where supported.
9. Tables must include a header row.
10. Align numeric columns right when comparative.
11. Use language tags in all fenced code blocks.
12. Keep code fences consistent (` ```python `, ` ```text `, ` ```bash `).

## Callout System

Use these callouts consistently:

- **📌 Definition** — framework term or concept
- **🔍 Example** — concrete usage
- **⚠️ Warning** — safety or consistency risk
- **💡 Note** — extra context
- **🎯 Key Insight** — core takeaway
- **✅ Verification** — how to validate outcomes

Template:

```markdown
> 📌 **Definition**
> One-paragraph canonical explanation.
```

## Diagrams and Visual Breaks

13. Add `---` between major conceptual segments.
14. Include diagram IDs near every embedded diagram.
15. Add captions under diagrams.
16. Use monospace fences for ASCII diagrams.
17. Keep diagram width readable in 80-120 character ranges.
18. Use alt-text for image diagrams.

## Emoji and Symbol Policy

19. Emoji is allowed in headings for navigation clarity.
20. Use one leading emoji max per heading.
21. Keep operator symbols inline as code.
22. Do not mix multiple symbol sets for the same operator.

## Publication Rules

23. Keep page-opening summary under 80 words.
24. Keep one key table per concept cluster when possible.
25. End each page with a navigation or next-step section.
